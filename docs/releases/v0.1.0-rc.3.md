# BYOK Grid 0.1.0-rc.3

<!-- release-version: 0.1.0-rc.3 -->

BYOK Grid is an open-source, fork-first workspace for building data-enrichment
tables and visual, node-based workflows with your own provider credentials.

## Release status

This is a prerelease for evaluation and production-readiness testing, not a
stable production release. It is the first candidate built around the shipped
no-account, SQLite-native single-node topology. It supersedes `v0.1.0-rc.2`,
whose signed tag remains immutable but whose failed image jobs prevented a
GitHub Release from being published.

There is no stable upgrade guarantee before `1.0.0`. Never move or reuse this
version tag; any release-blocking correction must use a new version.

## Highlights

- Removes signup, signin, sessions, and email authentication from the product
  path. A clone provisions one deterministic local owner and personal workspace
  without an identity service or delivery provider.
- Makes the durable SQLite outbox worker the default Node.js workflow runtime.
  It executes the same typed step handlers as the optional Hatchet adapter and
  drains in-flight workflow work cleanly on `SIGTERM`.
- Reduces the default Compose application to migration, Next.js web, and the
  SQLite-native workflow worker. Hatchet and PostgreSQL now start only through
  the explicit optional `hatchet` profile.
- Keeps the Next.js grid and React Flow editor for engineering published,
  versioned node workflows with filters, enrichment, formulas, writebacks, and
  signed webhooks.
- Adds a separate Next.js marketing site for Vercel while keeping the cloned
  application fully local and self-hosted.
- Replaces the infrastructure-specific stable gate with production-evidence
  schema v2. Stable release proof now covers source identity, security, release
  assets, two-platform image smoke, tag protection, default runtime drain, and
  SQLite backup/restore.
- Keeps remote libSQL, authenticated Hatchet, Kubernetes, public ingress,
  Airbyte, ClickHouse, native-host repetition, and capacity runbooks available
  as optional deployment claims rather than universal requirements.
- Continues to publish seven `linux/amd64` and `linux/arm64` images, a Helm
  chart, connector SDK, checksums, SBOMs, provenance, digest-bound smoke
  evidence, and immutable GitHub Release assets through the fail-closed release
  workflow.

The application release version is `0.1.0-rc.3`. The independently versioned
Apache-2.0 connector SDK remains `0.2.0`.

## Verify this release

Treat `IMAGE_DIGESTS.txt` as the authoritative container identity and verify all
downloaded files before deployment:

```text
sha256sum --check SHA256SUMS
npm run release:verify-bundle -- \
  --version 0.1.0-rc.3 \
  --directory /path/to/downloaded-release
```

Then verify GitHub attestations for the release files and exact GHCR digests.
The complete procedure is in the
[release verification guide](https://github.com/mherzog4/byok-grid/blob/v0.1.0-rc.3/docs/VERIFY_RELEASE.md).

## Known limits and production gates

The application intentionally has one local operator boundary, not multi-user
accounts or application-level authorization. Keep ordinary local use on
loopback. Any broader deployment needs an operator-controlled VPN,
identity-aware proxy, or equivalent access boundary, plus unique encryption
secrets, backups, monitoring, and an incident owner.

The default stable-product evidence is described in the
[production-readiness ledger](https://github.com/mherzog4/byok-grid/blob/v0.1.0-rc.3/docs/PRODUCTION_READINESS.md).
Deployments that claim Hatchet, remote libSQL, Kubernetes, public ingress,
Airbyte, ClickHouse, or a specific capacity envelope must also run the matching
optional runbooks. Report defects through the
[structured issue chooser](https://github.com/mherzog4/byok-grid/issues/new/choose)
and disclose vulnerabilities according to
[SECURITY.md](https://github.com/mherzog4/byok-grid/blob/v0.1.0-rc.3/SECURITY.md).
