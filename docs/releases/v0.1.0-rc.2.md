# BYOK Grid 0.1.0-rc.2

<!-- release-version: 0.1.0-rc.2 -->

BYOK Grid is an open-source, SQLite-first workspace for building collaborative
data-enrichment tables and visual, node-based workflows with credentials
supplied by each workspace.

## Release status

This is a prerelease for evaluation and production-readiness testing, not a
stable production release. It supersedes the aborted `v0.1.0-rc.1` candidate,
whose signed tag remains immutable but whose images and GitHub Release were not
published after the container vulnerability gate failed closed.

There is no stable upgrade guarantee before `1.0.0`. Never move or reuse this
version tag; any release-blocking correction must use a new version.

## Highlights

- Remediates the release-blocking Debian and npm runtime findings by moving to
  the digest-pinned Node.js 24.19.0 image and npm 12.0.2 for builds.
- Removes npm and npx from every production Node image through one verified
  runtime stage, reducing the shipped package-manager attack surface.
- Excludes development-only PostgreSQL, Drizzle Kit, and deprecated esbuild-kit
  tooling from the SQLite worker runtime, with build-time and realized-image
  absence checks.
- Adds fixable High/Critical OS and library vulnerability scanning for all seven
  locally built production images to ordinary CI, before a release tag exists.
- Preserves the SQLite source of truth, optional remote-libSQL topology, Next.js
  collaborative grid, React Flow workflow editor, durable Node.js workers, BYOK
  connectors, and optional Airbyte and ClickHouse adapters.
- Publishes seven `linux/amd64` and `linux/arm64` images only after immutable
  digest scanning, isolated smoke tests, attestations, anonymous pull checks,
  conflict-safe tag publication, and reproducible release packaging pass.
- Retains the fail-closed production evidence, release-protection, Kubernetes,
  ingress, SMTP, backup/restore, drain, rollback, and capacity gates required
  before a deployment can be promoted to stable production use.

The application release version is `0.1.0-rc.2`. The independently versioned
Apache-2.0 connector SDK remains `0.2.0`.

## Verify this release

Treat `IMAGE_DIGESTS.txt` as the authoritative container identity and verify all
downloaded files before deployment:

```text
sha256sum --check SHA256SUMS
npm run release:verify-bundle -- \
  --version 0.1.0-rc.2 \
  --directory /path/to/downloaded-release
```

Then verify GitHub attestations for the release files and exact GHCR digests,
and apply `values.digests.yaml` after operator-owned Helm values. Follow the
[release verification guide](https://github.com/mherzog4/byok-grid/blob/v0.1.0-rc.2/docs/VERIFY_RELEASE.md).

## Known limits and production gates

Before treating a deployment as production-ready, operators must validate their
remote libSQL and Hatchet services, TLS and trusted-proxy boundary, external
secret management, SMTP delivery, backup and restore, worker drain, capacity,
monitoring, alert routing, native architecture behavior, and rollback path.
Optional Airbyte and ClickHouse adapters require their own end-to-end evidence.

The authoritative remaining gates are in the
[production-readiness ledger](https://github.com/mherzog4/byok-grid/blob/v0.1.0-rc.2/docs/PRODUCTION_READINESS.md).
Report defects through the
[structured issue chooser](https://github.com/mherzog4/byok-grid/issues/new/choose)
and disclose vulnerabilities according to
[SECURITY.md](https://github.com/mherzog4/byok-grid/blob/v0.1.0-rc.2/SECURITY.md).
