# BYOK Grid 0.1.0-rc.1

<!-- release-version: 0.1.0-rc.1 -->

BYOK Grid is an open-source, SQLite-first workspace for building data-enrichment
tables and visual, node-based workflows with credentials supplied by each
workspace. This is the project's first public release candidate.

## Release status

This release is a prerelease for evaluation and production-readiness testing.
It is not yet a stable production release. Publishing it proves that the tagged
source, release files, and container images passed the repository's release
workflow; it does not prove that any particular deployment is production-ready.

There is no stable upgrade guarantee before `1.0.0`. Never move or reuse this
version tag; a release-blocking correction will use a new release-candidate
version.

## Highlights

- A Next.js workspace with collaborative, typed, sparse-cell tables, saved
  views, formula columns, streaming CSV import and export, and bounded bulk
  enrichment.
- A React Flow editor for engineering reusable node workflows with typed ports,
  immutable published versions, deterministic plans, filters, enrichment,
  writebacks, and signed webhooks.
- A SQLite source of truth for local and single-node installs, with remote
  libSQL as the supported multi-replica production topology.
- A Node.js workflow worker with durable Hatchet dispatch, idempotent execution,
  retries, cancellation, graceful drain, and just-in-time credential access.
- BYOK adapters for OpenAI Responses, Hunter Domain Search, guarded HTTPS,
  HubSpot contact import and writeback, and declarative community connectors
  isolated in an optional Wasmtime runner.
- Optional Airbyte destination and ClickHouse analytics-projector images. They
  are adapters, not dependencies of the SQLite application core.
- Compose and Helm deployment paths, seven multi-platform container images,
  exact image-digest manifests, SBOM and provenance attestations, checksums,
  digest-bound image-smoke evidence, and conflict-safe version-tag publication
  plus immutable GitHub Release publication that makes byte-identical workflow
  reruns a verified no-op rather than editing remote state. A separate
  read-only verifier binds active release-tag rules, the signed candidate tag,
  immutable release state, and all seven GHCR version tags to one retained
  stable-evidence marker, while a credential-free release gate proves every
  tag and digest is anonymously pullable before the GitHub Release is created.
- Encrypted workspace credentials, bounded master-key rotation, centralized
  tenant authorization, fail-closed signup controls, database-backed sessions,
  guarded network egress, and security-focused browser response boundaries.
- Structured public issue and pull-request intake, private security and conduct
  reporting paths, explicit best-effort support boundaries, and a fail-closed
  community-health verifier in the normal test suite.
- A bounded production SMTP evidence verifier that binds two controlled-inbox
  authentication deliveries to the candidate commit, trusted receiver results,
  and live enforcing SPF, DKIM, and DMARC records without publishing message
  bodies, addresses, links, or identifiers.
- A read-only Kubernetes runtime evidence verifier that binds stable live
  Deployments and Pod image IDs to the candidate's seven-image digest manifest,
  validates the retained migration, pod-security, TLS ingress, disruption
  budget, and policy shape, and emits no Secret names or values.
- An isolated Kubernetes NetworkPolicy enforcement drill that pairs every
  denied TCP path with an allowed same-target control and emits redacted,
  candidate-bound evidence from immutable NotReady probe pods.
- A read-only External Secrets Operator v1 provenance verifier that proves a
  recent explicit-key sync through a healthy store and digest-pinned hardened
  controller without fetching Secret data or publishing resource names.
- A controlled Kubernetes rollback drill that proves a named digest-pinned
  prior Helm revision becomes healthy, restores the exact candidate, attempts
  recovery after post-mutation failure, and binds the retained production
  evidence to an exact structured marker.
- A bounded two-network ingress drill that distinguishes application and edge
  rate limits, retains hashed forwarding-chain and trusted-proxy evidence,
  requires direct-origin denial, and closes the stable proxy-boundary claim.

The application release version is `0.1.0-rc.1`. The independently versioned
Apache-2.0 connector SDK remains `0.2.0`.

## Verify this release

Treat `IMAGE_DIGESTS.txt` as the authoritative image identity and verify the
six downloaded release files before deployment:

```text
sha256sum --check SHA256SUMS
npm run release:verify-bundle -- \
  --version 0.1.0-rc.1 \
  --directory /path/to/downloaded-release
```

Verify GitHub attestations for both release files and exact GHCR digests, then
apply `values.digests.yaml` after operator-owned Helm values. The complete
procedure is in the
[release verification guide](https://github.com/mherzog4/byok-grid/blob/v0.1.0-rc.1/docs/VERIFY_RELEASE.md).

## Known limits and production gates

Before treating a deployment as production-ready, operators must validate the
chosen remote libSQL and authenticated Hatchet services, TLS ingress and trusted
proxy boundary, external secret management, SMTP delivery, backup and restore,
worker drain, capacity envelope, native `linux/amd64` and `linux/arm64` image
smoke with the closed native multi-architecture evidence verifier, monitoring
and alert routing, and a rollback path. Optional Airbyte and ClickHouse adapters
must be exercised end to end before being included in a deployment's supported
matrix.

The remaining release gates and their required evidence are tracked in the
[production-readiness ledger](https://github.com/mherzog4/byok-grid/blob/v0.1.0-rc.1/docs/PRODUCTION_READINESS.md).
Please report defects through the
[structured issue chooser](https://github.com/mherzog4/byok-grid/issues/new/choose),
read the
[support policy](https://github.com/mherzog4/byok-grid/blob/v0.1.0-rc.1/SUPPORT.md),
and disclose security vulnerabilities according to
[SECURITY.md](https://github.com/mherzog4/byok-grid/blob/v0.1.0-rc.1/SECURITY.md).
