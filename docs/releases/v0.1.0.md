# BYOK Grid 0.1.0

<!-- release-version: 0.1.0 -->

BYOK Grid is an open-source, fork-first workspace for building data-enrichment
tables and visual, node-based workflows with your own provider credentials.

## Release status

This is the first stable release of the default BYOK Grid product: a no-account
Next.js application, a SQLite-native Node.js workflow worker, and one
authoritative SQLite database. It promotes the independently verified
`v0.1.0-rc.3` candidate through a metadata-only change set; no runtime,
dependency, workflow, deployment template, or verifier code changed after that
candidate.

The stable support promise covers the default single-node topology. A broader
deployment still needs an operator-controlled access boundary, secrets,
backups, monitoring, and incident ownership appropriate to that environment.

## Highlights

- Ships a fast virtualized grid for importing, filtering, enriching, computing,
  exporting, and writing back structured data.
- Ships a React Flow editor for engineering published, versioned workflows with
  typed inputs, filters, formulas, provider enrichment, HTTP calls, writebacks,
  and signed webhooks.
- Uses a deterministic local owner and personal workspace without signup,
  signin, sessions, invitations, password recovery, or application email
  delivery.
- Runs durable workflows through the SQLite outbox by default and completes
  in-flight work cleanly during worker and web shutdown.
- Keeps provider credentials encrypted under operator-owned master keys and
  decrypts them only at the execution boundary.
- Starts only a one-shot SQLite migrator, Next.js web process, and SQLite-native
  workflow worker in the default Compose profile.
- Includes a separate Next.js marketing site deployable to Vercel while the
  cloned application remains local and self-hosted.
- Publishes seven `linux/amd64` and `linux/arm64` container images, a Helm chart,
  connector SDK, checksums, SPDX SBOMs, provenance, digest-bound smoke evidence,
  and immutable release assets through the fail-closed release workflow.

The independently versioned Apache-2.0 connector SDK remains `0.2.0`.

## Known limits and production gates

The supported stable product is the default single-node SQLite topology.
Hatchet, remote libSQL, Kubernetes, public ingress, Airbyte, ClickHouse,
native-host image repetition, and deployment-specific capacity claims remain
available as optional operator choices, but they are not certified by this
release's default production-evidence manifest.

The application intentionally provides one local operator boundary rather than
multi-user accounts or application-level authorization. Keep ordinary local
use on loopback. Put any broader deployment behind a VPN, identity-aware proxy,
or equivalent operator-controlled boundary.

## Verify this release

Treat `IMAGE_DIGESTS.txt` as the authoritative container identity and verify all
downloaded files before deployment:

```text
sha256sum --check SHA256SUMS
npm run release:verify-bundle -- \
  --version 0.1.0 \
  --directory /path/to/downloaded-release
```

Then verify GitHub attestations for the release files and exact GHCR digests.
The complete procedure is in the
[release verification guide](https://github.com/mherzog4/byok-grid/blob/v0.1.0/docs/VERIFY_RELEASE.md).

## Upgrade and compatibility

The stable promotion contains release metadata only, so the database schema and
runtime behavior are identical to `v0.1.0-rc.3`. Run the one-shot migration
image before web and worker processes, retain the previous database and keys,
and complete an online backup plus isolated restore test before replacing an
existing installation.

The public APIs and connector contracts are still pre-1.0 interfaces and may
evolve in later minor releases. Versioned database migrations remain forward
only; restore a verified backup rather than attempting to reverse a migration.
